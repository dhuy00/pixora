Technical Specification & Architecture: Pixaura

Full-stack engineering design for Pixaura's hybrid architecture: a high-frequency client-side 2D Canvas Studio Engine (supporting 512×512 multi-layer animations, off-thread quantization, and local-first IndexedDB persistence) paired with a Next.js App Router & PostgreSQL community platform.

Next.js 15 (App Router) TypeScript 5 HTML5 2D Canvas + Uint32Array Zustand + Immer Web Workers (image-q + gifenc) Dexie.js (IndexedDB) PostgreSQL + Drizzle ORM Cloudflare R2 / Supabase Storage

01 System Architecture Overview

Pixaura separates interactive pixel manipulation from server-rendered community discovery. All drawing, onion skinning, quantization, and export tasks run with zero network latency on the client, while project synchronization, authentication, and gallery feeds run through typed Next.js route handlers and PostgreSQL.

1. Browser Client60–120 FPS
React 19 + Tailwind + Radix UI Studio docks, modals, color popovers, gallery grids, and keyboard shortcut manager.
Zustand Studio Store Decouples pointer events from React renders; manages layers, frames, tools, and palettes.
HTML5 2D Canvas Engine 4 stacked canvases backed by sparse Uint32Array RGBA buffers per [Frame, Layer] cel.
Web Worker Pool Off-main-thread image-q quantizer/dithering & gifenc animated GIF encoder.
IndexedDB (Dexie.js) Local-first guest drafts, compressed cel buffers, and offline crash recovery.
2. Next.js Edge / ServerSSR + API
App Router RSC Pages Server-rendered Explore feed (/), Artwork Detail (/art/:postId), and Creator Profiles (/u/:username).
REST / RPC Route Handlers Zod-validated endpoints for project sync, guest migration, post publishing, and social actions.
Authentication Guard Supabase Auth / Better Auth managing sessions, OAuth, and verified-email enforcement.
Rate Limiter & Validator Token-bucket rate limiting (comments 5/min, uploads 10/10min) + magic-byte MIME verification.
3. Persistence & StorageACID + CDN
PostgreSQL 16 (Drizzle ORM) Relational store for Users, Projects, Layers, Frames, Cels, Source Images, Posts, Tags, and Social graphs.
Object Storage (R2 / Supabase) Stores immutable SOURCE_IMAGE uploads (≤10MB) and rendered POST previews (PNG/GIF/WebP).
Global Edge CDN Serves published pixel art previews with immutable cache headers and crisp nearest-neighbor scaling.

04 Studio Engine & Canvas Architecture

Replacing the prototype's DOM-based grid (which creates W × H HTML elements) is critical: a 512×512 canvas contains 262,144 pixels per layer. Pixaura uses a 4-Plane HTML5 2D Canvas Stack backed by raw Uint32Array pixel buffers.

4.1 Multi-Plane Viewport Stack

60–120 FPS Rendering
Plane 4: Interaction & Tool Preview Overlay (Screen Resolution)
Renders crisp 1px grid lines (at zoom ≥ 800%), brush cursor outline, and uncommitted shape previews (Line, Rectangle, Circle) during pointer drag.
z-index: 40
Plane 3: Composite Artwork Canvas (Project Width × Height)
Alpha-blends all visible layers of the active frame from bottom to top. Scaled via CSS image-rendering: pixelated (100%–6400%).
z-index: 30
Plane 2: Onion Skin Canvas (Project Width × Height)
Displays translucent overlays of 1–3 previous frames (red tint) and 1–3 next frames (blue/cyan tint).
z-index: 20
Plane 1: Checkerboard Transparency Backdrop (Project Width × Height)
Cached repeating pattern indicating transparent pixels; only redraws on canvas resize.
z-index: 10

4.2 Cel Memory Model ([Frame, Layer] Matrix)

Sparse Typed Arrays
Pixel Representation
Each cel is stored as a Uint32Array(width * height) where each element packs a 32-bit RGBA pixel (0xAABBGGRR on little-endian CPUs), sharing its underlying ArrayBuffer directly with ImageData.
Memory Budget
  • A single 512×512 cel consumes exactly 512 × 512 × 4 bytes = 1.0 MB.
  • Sparse Allocation: Empty cels do not allocate a 1MB buffer until a pixel is drawn.
  • Deflate Compression: When persisted to IndexedDB or PostgreSQL BYTEA, browser-native CompressionStream('deflate-raw') shrinks a 1MB pixel-art cel to 10–45 KB.

4.3 Pixel-Perfect Drawing & Raster Algorithms

Integer Grid Math
Pencil & Eraser
Interpolates between consecutive pointer events (x0, y0) → (x1, y1) using Bresenham's Line Algorithm and stamps a configurable 1px–8px brush mask so fast cursor movement never leaves gaps.
Shape Tools
  • Line Tool: Integer Bresenham line rendered live on Plane 4 during drag, committed to active cel on pointerup.
  • Rectangle Tool: Axis-aligned outlined or filled box between anchor (x0, y0) and cursor (x1, y1).
  • Circle Tool: Midpoint Circle/Ellipse Algorithm generating symmetrical, anti-alias-free pixel perimeters.
Flood Fill (Bucket)
  • Contiguous Fill: Iterative scanline 4-way flood fill backed by a pre-allocated Int32Array ring queue (prevents recursion stack overflow at 512×512).
  • Global Color Replace: Single linear pass replacing all matching Uint32 color values across the active cel.

4.4 Command-Pattern Undo / Redo Engine (50+ Steps)

Delta Patch Stack

To support at least 50 sequential undo/redo operations without exhausting memory, the History Manager records compact delta patches per action:

export type HistoryCommand =
  | {
      type: 'CEL_DELTA';
      celKey: `${string}:${string}`; // `${frameId}:${layerId}`
      boundingBox: { x: number; y: number; w: number; h: number };
      beforePatch: Uint32Array;      // Sub-rectangle buffer prior to stroke
      afterPatch: Uint32Array;       // Sub-rectangle buffer after stroke
    }
  | {
      type: 'PROJECT_STRUCTURE';
      mutation: 'LAYER_ADD' | 'LAYER_DELETE' | 'LAYER_REORDER' | 'FRAME_ADD' | 'FRAME_DELETE' | 'FRAME_REORDER';
      beforeState: StructuralSnapshot;
      afterState: StructuralSnapshot;
    };

05 Animation & Export Pipeline

Timeline Playback & Frame Hold Engine

Driven by a high-precision requestAnimationFrame loop. Each frame resolves its duration via:

durationMs = frame.durationOverrideMs ?? Math.round(1000 / project.fps)

  • Supports Forward Loop, Ping-Pong (alternating direction), and Once.
  • Synchronizes both the main canvas viewport and the floating 1x/2x Mini-Preview window.
  • Enforces PRD limits: 1–64 frames, 1–30 FPS, 20ms–5000ms frame holds.

Client-Side Export Pipeline (PNG, GIF, Sprite Sheet)

  • Crisp Scaled PNG (1x, 2x, 4x, 8x, 16x): Renders onto an OffscreenCanvas of size (W × scale, H × scale) with imageSmoothingEnabled = false.
  • PNG Sprite Sheet Packer: Packs all frames into a Horizontal Strip ((W×N) × H), Vertical Strip (W × (H×N)), or balanced Grid Layout.
  • Animated GIF Worker (gifenc): Quantizes each composited frame to a 256-color table (reserving 1 transparent index) and encodes frame delays in a background Web Worker.

06 Image-to-Pixel Art Converter Pipeline

The converter runs inside a dedicated Web Worker (converter.worker.ts) using image-q so adjusting sliders (Resolution, Color Count, Dithering) updates the split-slider preview in under 50ms without blocking the main UI thread.

1. Upload & Preserve

Validates magic bytes for PNG, JPG, or WebP (≤10MB, ≤4096×4096). Stores the untouched original file as a separate SOURCE_IMAGE record before any pixel processing occurs.

2. Downsample & Quantize

Applies aspect-aware crop/fit and downsamples to target pixel dimensions (8×8 to 512×512). Runs WuQuant / NeuQuant to extract 2–64 optimal colors or maps to an active project palette.

3. Dither & Import

Applies selectable dithering (None, Bayer Ordered, or Floyd-Steinberg). Importing creates a new project or layer, populates the project palette, and links source_image_id for future re-conversion.

07 State Management, Auto-Save & Guest Migration

Local-First Auto-Save & Cloud Sync

  1. Immediate Local Write: Every stroke or layer edit marks touched cels as dirty and writes deflated buffers to IndexedDB (pixaura_local via Dexie.js).
  2. 30-Second Cloud Sync: For authenticated users, a debounced background worker batches dirty cels every 30s (or immediately on Ctrl/Cmd + S) to PUT /api/projects/:id/sync.
  3. Draft Isolation: Cloud sync updates only projects, layers, frames, and cels. A linked public POST remains untouched until the user clicks Update Published Post.

Guest-to-Registered Session Migration

  1. Guest Session: Unauthenticated visitor draws, animates, or converts an image in /studio. Full project state lives in IndexedDB with isGuestDraft = true.
  2. Auth Trigger: Visitor clicks Save to Cloud or Publish and completes /login or /register.
  3. Automatic Migration Hook: On auth redirect, client detects isGuestDraft, posts the payload to POST /api/projects/migrate, and transitions seamlessly to /studio/:newProjectId.

10 Security, Validation & Performance Budgets

Security & Access Control

  • Magic-Byte File Inspection: Rejects disguised executables by verifying raw binary signatures for PNG, JPEG, and WebP before decoding image dimensions.
  • Strict Plain-Text Sanitization: Comments and bios are rendered as text nodes; zero raw HTML/Markdown injection vectors.
  • Ownership Guardrails: Draft projects and reference images are strictly isolated to project.user_id; comments can be deleted by either the comment author or the post owner.

Performance Budgets

  • Pointer-to-Pixel Latency (< 8ms): Direct Uint32Array writes + dirty-rect putImageData bypass React reconciliation during active brush strokes.
  • Converter Live Preview (< 100ms): Off-main-thread Web Worker caches the cropped source bitmap and re-runs quantization smoothly as sliders move.
  • Crisp Gallery Rendering (LCP < 1.5s): Server-rendered feed cards with image-rendering: pixelated and viewport-triggered animation playback.
